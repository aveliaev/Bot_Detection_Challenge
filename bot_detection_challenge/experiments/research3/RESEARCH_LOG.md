# Research cycle 3 — log

Question of the cycle: not "is it a bot?", but "does this cookie look like one of the **known scraping services**?"
Focus: the ~45 negatives that every model ranks as bots (persistent FP).

Conventions
- `rep` = repeated day-block CV, mean over partitions P0–P4 (cycle-2 harness `research2/rcv.py`); `fwd7` = test-like forward check.
- Noise floor for decisions: std between partitions ≈ 0.004 → |Δ| < 0.01 is noise.
- "TPnear" = true positives at OOF rank 300–604 (the region where the FPs live); "pFP" = persistent FP (below).
- AUC(TPnear vs pFP / FP) is the discovery metric of the cycle (point 26). With 45–59 FP its standard error is ≈ 0.04–0.05.
- Discovery tables that use all labels are **descriptive only**. Everything that is fed to a model, or that
  measures a "future-day" AUC, is built from training days only (fold labels; inner leave-one-day-out for training rows).
- OOF of every integration candidate: `research3/oof/<exp>__{P0..P4,fwd7}.npy` (not in git, regenerated by scripts); summary rows: `research3/experiments3.jsonl`.

## C3.2 Matched pairs and counterfactual reasons
`r2_pairs.py`: each FP → nearest TP (quantile-normalised B0 feature space), paired Wilcoxon on raw characteristics.
Only activity differs after matching: FP have fewer items (10 vs 12, p = 0.002) and events (21 vs 28, p = 0.007), slightly fewer
3–10 s delays (p = 0.04). Pointer σ, pool share, UA, cookie age, edge clicks: p > 0.2. Reverse direction (TPnear → nearest negative):
TPs have fewer 30–90 s delays and higher pool LLR — the same signals the model already uses.

`r2_shap.py` (CatBoost SHAP on P0 fold models, grouped by family). Mean contribution to the persistent FP vs TPnear:
pool 2.46 vs 1.73, pointer 2.11 vs 1.76, items/diversity 1.11 vs 0.79, timing 0.98 vs 1.33. FP reason clusters (k = 3):

| type | n | driver | comment |
|---|---|---|---|
| R0 | 21 | item pool (+3.7 log-odds) | humans browsing the bot pool at bot rate |
| R1 | 10 | pointer (+5.4) | bot pointer generator |
| R2 | 14 | timing + activity (+1.9 / +1.3) | fast-ish, active, pool |

Each type is 10–21 cookies; a specialist per type (point 25) has no statistical power (AUC SE ≈ 0.09) and each type is defined by
channels that F3/F7 showed to be identical to bots → specialists not trained.

## C3.3 Service clustering (known bots only) — `r3_clusters.py`, `r3_profile.py`
5 representations (all / behaviour / sequence+timing / technical / all-but-category) × KMeans, GMM, Agglomerative (k = 2–8), HDBSCAN.
Stability = ARI between a week-1 fit applied to week 2 and a week-2 fit.
- Stable (ARI ≥ 0.9): only the technical split (web / android / iOS × pointer mode), silhouette 0.28–0.39.
- Behavioural clusters: ARI 0.2–0.6, silhouette ≤ 0.2; **HDBSCAN on behaviour finds no cluster at all** (all 899 bots = noise).
- The six KMeans subtypes (all-rep): web crawler (fast, deep, scraper UA; recall 0.85), android app/browser (0.46), iOS (0.31),
  web pointer with edge clicks (0.64), web compressed pointer (0.74), web without pointer, slow (0.56). Week-2 share 0.45–0.47 in all.
- FP distance to the nearest bot prototype: median 4.28 vs 4.55 for bots themselves (42nd percentile) — FP are **central**, not outliers.

## C3.4 / C3.6(2D) Positive manifold, prototypes, one-class — `manifold.py`, `r4_manifold_disc.py`, `r6_2d.log`
Strict OOF: validation rows scored against all training-fold positives; training rows against other training days only.
Scores: kNN distance to bots / humans, IsolationForest on bots, GMM log-density (bots, humans, ratio), Ledoit-Wolf Mahalanobis,
sorted prototype distances. Three representations.

| representation | best AUC bot vs human | AUC TPnear vs FP (range over 11 scores) |
|---|---|---|
| all blocks | 0.86 (gmm ratio) | 0.40 – 0.61 |
| behaviour only | 0.86 | 0.41 – 0.60 |
| pointer + timing | 0.85 | 0.44 – 0.54 |

Direction is **opposite** to the hypothesis: pFP are *closer* to the bot manifold than TPnear (kNN-to-bots 0.57–0.60,
Mahalanobis 0.60–0.61). 2D table (generic rank × service-likeness quartile), ranks 300–604: FP 7 / 6 / 12 / 25 vs TP 56 / 40 / 54 / 104
from low to high service-likeness. The "generic high, service low" corner holds 8 FP vs 84 TP (91% precision, no enrichment).
Density check (`r10_negclust.py`): pFP percentiles under a bot GMM are spread 0.03–0.96 (typical bots), under a human GMM median 0.14.
→ hypothesis "FP are automation that is not like any known service" **rejected**.

## C3.8 Timing generator — `r8_sessions.py`, `r10_dtseq.py`
No sleep(n) spikes, no quantisation, no scheduler. Exact delay 4-grams are shared with another bot for 14.3% of bot 4-grams
(humans 0.1%, pFP 0.6%) — but a within-cookie shuffle keeps the rate (0.147 → 0.147) while a global shuffle kills it (0.01):
narrow per-cookie delay distributions, **not replayed templates**. Already represented by `dtexact_uniq_ratio`, `dtbin_ent`.

## C3.14 Robustness
- Leakage tests `research3/test_leakage3.py`: llr(all), manifold, llr(trait) — own-day labels of training rows do not reach own features (ok);
  uate — same-day/future labels (ok); llr(hard) — FAIL (hard set chosen by inner models that saw the row's day) → fixed as E5_llrtrait.
- Adversarial (final setting): pool 0.63, llr hard/trait/all 0.81/0.80/0.75, manifold 0.71, uate 1.00.
- Submission reproducibility: `solution/train_final_v2.py` re-run → bit-identical `submission.csv` (Spearman 1.0, max |diff| 0).
- Ceiling simulation (`r15_ceiling_sim.py`): an extra signal independent of B0 with bot-vs-human AUC 0.60 / 0.65 / 0.70 / 0.75 / 0.80 / 0.90 adds at most
  +0.0005 / +0.003 / +0.004 / +0.014 / +0.026 / +0.061 (weight tuned in-sample). 0.93 needs AUC ≈ 0.80 from a channel B0 does not have.

## Conclusion (point 29)
All planned directions were run: service prototypes, positive manifold, event LLR, discriminative motifs, exact fingerprints,
pointer generator, timing generator, coverage strategy, negative clustering, hierarchical and multiclass models, android fingerprints.
None gives a stable gain > 0.01; none removes a single persistent FP beyond noise (44–45 of 45 remain flagged in every candidate).
The 45 persistent FP are produced by the same pointer generator and the same item-pool process as the known bots and differ only in
rhythm/activity, which B0 already uses. The available fields do not contain enough information to separate known services from the
bot-like target-0 traffic. B0 and the cycle-2 `submission.csv` (hidden test 0.8953) are kept.
