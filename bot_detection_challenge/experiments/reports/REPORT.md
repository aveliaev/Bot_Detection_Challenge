# Итоги работы: bot detection

Итог: решение с **P@R≥0.70 = 0.896** на основной валидации и **0.893** на валидации, устроенной как test. Файл для сдачи — `submission.csv`. Код воспроизводимый, всё лежит в ветке `claude/busy-gauss-xlnasc`.

Для сравнения: доля ботов (уровень константы) — 0.081, baseline из quickstart — около 0.116.

---

## Что сделано

1. **Изучил данные до обучения моделей.** Разобрал все файлы: схему, окна, пропуски, дубликаты, платформы, user agent, пересечения train/test. Сравнил распределения у ботов и людей.
2. **Проверил метрику.** Официальный `metric.py` сверил с собственной независимой реализацией на тестах: одинаковые score, немонотонный пример, 2000 случайных проверок, перестановка строк.
3. **Построил около 310 признаков на cookie.** Активность, интервалы между событиями, типы событий и их последовательности, объявления, поиск, курсор, user agent, время суток, пропуски, последние N минут. Отдельный модуль — признаки «пула объявлений» со строгим соблюдением времени.
4. **Собрал три схемы валидации** с сохранением OOF-предсказаний для каждого эксперимента:
   - блоки по дням — основная;
   - «вперёд на 7 дней» — повторяет устройство test;
   - случайная стратифицированная — для сравнения.
5. **Прогнал около 60 экспериментов.** Семейства признаков добавлялись по одному, затем ablation (убрать семейство, 3 seed). Семь типов моделей, локальный тюнинг, веса классов, отбор признаков, бленд.
6. **Провёл adversarial validation и разбор ошибок** около recall = 0.70.
7. **Обучил финальную модель на всём train**, сделал submission и написал отчёт (`README_SOLUTION.md`).

---

## Что получилось

### Найдены и исключены утечки
- **События после конца окна.** В train их 40 779 (у ботов 42% событий), в test их нет. Модель, обученная на них, получила бы красивый CV и провалилась бы на test.
- **`captcha_shown`.** Встречается *только* после окна, у 441 из 899 ботов — это последствие того, что бот уже пойман, а не признак. Не используется.
- **Мой собственный признак популярности** в первой версии оказался «отпечатком дня»: adversarial validation отделяла train от test с AUC 0.995. Нашёл причину — нормировка на число cookie за день — и исправил. Без признаков по объявлениям train и test не различаются (AUC 0.51).

### Найдены настоящие закономерности
| сигнал | что видно | вклад |
|---|---|---|
| **Общий пул объявлений** | боты смотрят объявления из устойчивого набора: 52% объявлений у ботов второй недели уже встречались у ботов первой (у людей 9%) | +0.08 на test-подобной валидации; почти не слабеет при разрыве до 7 дней |
| **Курсор** | у людей координаты равномерны по экрану, у ботов сжаты в центр, плюс ровно 0 и края 1080/1920 | самое важное семейство: без него 0.881 → 0.831 |
| **Паузы между действиями** | 58% пауз у ботов — 3–20 с (у людей 20%); пауз 0–2 с у ботов меньше, похоже на скрипт с минимальной задержкой | второе по важности семейство |
| Разнообразие | боты смотрят больше городов и категорий, глубже листают выдачу, у них моложе cookie | полезно, но дублирует сигналы выше |

Каждое семейство по отдельности даёт P@R 0.3–0.6, а вместе — 0.88+. Сигнал в сочетаниях признаков.

### Честная валидация
- Разные схемы CV согласуются, провальных фолдов нет:
  - блоки по дням: 0.86–0.95 по фолдам;
  - test-подобная: 0.89–0.91 по фолдам.
- Решения принимал только по OOF и на обеих схемах, учитывая шум метрики (около ±0.013).

### Модели
| модель | P@R (блоки по дням) | P@R (как test) |
|---|---|---|
| Logistic Regression | 0.820 | 0.707 |
| LightGBM | 0.883 | 0.874 |
| XGBoost | 0.885 | 0.868 |
| ExtraTrees | 0.884 | 0.880 |
| CatBoost | 0.891 | 0.890 |
| CatBoost, 120 отобранных признаков | 0.894 | 0.892 |
| **Финал: CatBoost 0.6 + ExtraTrees 0.2 + XGBoost 0.2** | **0.896** | **0.893** |

В рабочей точке 606 cookie помечено ботами при precision 0.896 и recall 0.703. PR-AUC финала 0.842, ROC-AUC 0.955.

## Что не получилось или не дало эффекта

- **User agent.** Даже явные скрейперские UA (curl, Scrapy, python-requests) — лишь 19–27% ботов. Модель на char TF-IDF по UA даёт 0.12 — почти уровень константы.
- **TF-IDF по последовательностям событий** даёт 0.28 сам по себе и ничего не добавляет в бленде.
- **Тюнинг гиперпараметров.** Глубина, регуляризация, learning rate и число деревьев — всё в пределах шума (0.88–0.90).
- **Веса классов** не помогли ни CatBoost, ни LightGBM.
- **Признаки последних 5/15/30/60 минут окна, время суток, пропуски** оказались бесполезны или избыточны.
- **Полосы интервалов и «зона» курсора**, добавленные после анализа ошибок, дали лишь +0.003…0.01 — в пределах шума.
- **Мобильные боты.** Качество внутри платформы (P@R): web 0.91, android 0.58, iOS 0.18. На телефонах нет курсора, а другие сигналы слабее. Хуже всего ловятся cookie с 1–3 событиями. Отдельного решения для мобильных найти не удалось.
- **Ложные срабатывания у порога** по всем признакам выглядят как боты: быстрые, много городов, объявления из пула, молодая cookie. Скорее всего, это неразмеченные боты или шум в метках. Моделью это не исправить, и здесь, похоже, потолок качества.
- **Полная детерминированность.** Повторный запуск даёт score с расхождением до 0.00004 из-за многопоточности CatBoost/XGBoost. На порядок cookie это практически не влияет, но бит-в-бит файлы не совпадают.
- **Отбор 120 признаков** даёт прирост +0.005, это на грани шума. Отбор сделан по важности на тех же данных, поэтому оценка может быть слегка оптимистичной.

---

## Риски для hidden test
- Разрыв test с последней размеченной датой — 1–7 дней. Объявления живут около 8 дней, поэтому к концу test-недели сигнал пула немного слабеет. На валидации падение небольшое: 0.877 → 0.866.
- Бленд выбран на плоской поверхности весов. Прирост от него над одиночным CatBoost (около +0.005) может не воспроизвестись.
- Если в test другая доля мобильных ботов, итоговая метрика сдвинется: на мобильных модель заметно слабее.

## Что можно попробовать дальше
- Отдельную модель или отдельные признаки для мобильных (android/iOS) cookie.
- Признаки совместных просмотров между cookie без меток (граф cookie–объявление) с тем же строгим ограничением по времени.
- Больше seed и повторённый day-block CV, чтобы надёжнее различать решения с разницей около 0.01.
