# Bot Detection Challenge

Решение задачи детекции ботов по событиям cookie.

**Итоговый результат:** Precision при Recall ≥ 70% на скрытом test — **0.8953**.

## Запуск итогового решения

Для проверки нужен только каталог `bot_detection_challenge/`. Код экспериментов запускать не требуется.

Требования:

- Python 3.11;
- около 1–2 минут на 4 CPU для построения `submission.csv`;
- входные данные в `bot_detection_challenge/data/`.

```bash
cd bot_detection_challenge

python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt

python3 solution.py
```

Результат будет записан в:

```text
bot_detection_challenge/submission.csv
```

Формат файла:

```text
cookie_id,score
```

В файле должна быть 4909 строк — по одной для каждой cookie из `data/test.csv`.

Повторный запуск с теми же данными и зависимостями воспроизводит итоговый файл. Все источники случайности зафиксированы.


## Итоговый подход

Всё финальное решение находится в одном файле — [`bot_detection_challenge/solution.py`](bot_detection_challenge/solution.py).

Пайплайн:

1. Оставляет события только внутри окна наблюдения cookie и удаляет точные дубликаты.
2. Строит поведенческие признаки: активность, паузы и сессии, координаты курсора, события, объявления, категории, города, поиск и User-Agent.
3. Добавляет временные признаки по объявлениям, используя только доступную на соответствующий момент историю.
4. Обучает пять CatBoost-моделей с разными фиксированными seed.
5. Усредняет ранги предсказаний и записывает `submission.csv`.

`cookie_id` используется только как ключ соединения и не передаётся модели как признак. События после `window_end_ts` и `captcha_shown` исключены как источник утечки.

## Валидация и результат

Так как test расположен позже train, основной способ проверки — временная валидация, а не случайный KFold.

| Модель | Повторная day-block CV | fwd7 |
|---|---:|---:|
| Константа | 0.081 | 0.081 |
| Baseline из quickstart | 0.098 ± 0.001 | 0.093 |
| CatBoost, признаки одной cookie | 0.872 ± 0.003 | 0.833 |
| **Итоговая модель** | **0.896 ± 0.006** | **0.901** |
| **Скрытый test** | — | **0.8953** |

Подробное описание признаков, валидации, защиты от утечек и ограничений модели: [`bot_detection_challenge/README.md`](bot_detection_challenge/README.md).

## Краткий обзор экспериментов

Исследование проходило в семь циклов. Помимо финального CatBoost проверялись:

- LightGBM, XGBoost, ExtraTrees, логистическая регрессия и ансамбли;
- граф cookie ↔ объявление и признаки общего пула объявлений;
- отдельные модели для web и mobile;
- кластеризация и поиск устойчивых «сервисов» ботов;
- независимые детекторы по группам сигналов и их слияние;
- локальное переранжирование примеров около рабочего порога;
- self-supervised признаки и межканальные остатки;
- признаки последовательностей, окон событий, кинематики курсора, LSTM и BiLSTM.

### Проверка подходов из опубликованных работ

В отдельных циклах были воспроизведены и адаптированы подходы из близких задач детекции ботов:

1. **[IEEE ISIT 2024 — Bits and Bots](https://www.kaggle.com/competitions/isit-2024-bits-and-bots)** — соревнование по детекции и атрибуции ботов на основе движений мыши и других событий взаимодействия с сайтом. Были проверены подходы из решений победителей: признаки на локальных окнах событий, кинематика курсора, классификация фрагментов последовательности, LSTM и BiLSTM. На наших данных они не перенеслись: лучший вариант дал 0.899 на повторной CV и 0.884 на fwd7 против 0.900/0.902 у итоговой модели. Подробности: [`REPORT_CYCLE7.md`](bot_detection_challenge/experiments/reports/REPORT_CYCLE7.md).

2. **C. Iliou et al., [“Detection of Advanced Web Bots by Combining Web Logs with Mouse Behavioural Biometrics”](https://doi.org/10.1145/3447815), ACM Digital Threats: Research and Practice, 2021** — были построены отдельные детекторы по каналам mouse / behavior / item и проверено их слияние на уровне решений, включая схему с порогами уверенности из статьи. Лучший вариант дал 0.892 на повторной CV и 0.886 на fwd7, поэтому не заменил единую модель. Подробности: [`REPORT_CYCLE4.md`](bot_detection_challenge/experiments/reports/REPORT_CYCLE4.md).

Эти работы использовались как источники проверяемых гипотез, но их методы **не включены в итоговый `solution.py`**, поскольку не дали устойчивого улучшения на обеих временных схемах валидации.

Ни один вариант не дал устойчивого улучшения одновременно на повторной временной CV и на fwd7. Поэтому итоговым оставлен более простой однофайловый CatBoost-пайплайн.

Полная карта экспериментов, результаты каждого цикла и ссылки на подробные отчёты: [`bot_detection_challenge/experiments/README.md`](bot_detection_challenge/experiments/README.md).

## Структура репозитория

```text
bot_check/
├── README.md
└── bot_detection_challenge/
    ├── solution.py             # итоговое решение
    ├── requirements.txt        # зависимости итогового решения
    ├── metric.py               # официальная метрика
    ├── data/                   # train, test и события
    ├── sample_submission.csv
    ├── submission.csv          # воспроизведённый итоговый ответ
    ├── README.md               # подробный технический отчёт
    └── experiments/            # исследовательский код, логи и отчёты
```

Для обычной проверки достаточно установить `requirements.txt` и запустить `solution.py`. Содержимое `experiments/` не участвует в построении итогового ответа.
